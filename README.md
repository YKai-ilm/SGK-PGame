# 三哥走防與三哥吞食

遊戲名稱統一：**三哥走防**為塔防版；**三哥吞食**為五對五指令戰鬥版。兩者共用劇情與素材資料，各自保存進度與戰鬥規則。現有專案路徑、GitHub／部署識別與存檔鍵維持，避免改名破壞既有連結及玩家進度。

三哥吞食正式入口為 `https://sgk-pgame.pages.dev/swallow/`，可加入主畫面；來源在 `variants/five-v-five`，從主城→劇情出征→桃源村開始。三哥走防保留根網址。兩者同一倉庫、同一次發布，三哥吞食建置直接沿用桃園起兵對話／場景來源，僅轉換存檔命名空間及戰鬥銜接；不複製維護第二份劇情。各自 PWA scope、離線包與進度，後續章節須逐段完成五對五銜接才開放。

手機與桌面共用的網頁遊戲。正式入口為 `index.html`，遊戲主介面為 `主介面流程預覽.html`。

正式網址：https://sgk-pgame.pages.dev/ 。手機及電腦均使用此網址；手冊位於 `/行旅手冊.html`。

電腦本機也可直接開啟 `主介面流程預覽.html`。載入本機自動更新功能後，每五秒檢查一次建置完成的版本標記；回主城且未進行對話、編隊或教學時，自動重新載入，不清除本機存檔。第一次接入功能時，舊分頁需手動重新整理一次。內嵌手機模擬頁的主介面也適用。場景與戰鬥頁不強制刷新，回到主介面時載入新程式。

## 建置與發布

需要 Node.js 22 以上，首次先執行 npm ci 安裝建置用的圖片壓縮工具（sharp）。

```
npm test
npm run build
npm run preview
```

Cloudflare Pages：連接 `YKai-ilm/SGK-PGame`，正式分支 `main`，建置命令 `npm test && npm run build`，輸出 `dist`，Node.js 22。

修改、驗證完成後執行 `npm run release -- "本次修改說明"`。這會測試、建置、提交遊戲需要的檔案並推送 main，由 Cloudflare 自動發布；不監看每一次檔案存入，以免發布半成品。僅使用這個專案的 origin，不影響其他遊戲。

建置根據檔案引用收集資源，來源 PNG 保留於本機及 GitHub；發布時轉成原尺寸、品質88的 WebP。玩家離線包僅下載壓縮版（全部目前約22MB，首次基本資料及第一章約15MB），.asset-cache 保留本機壓縮結果加速後續建置。`dist` 不直接提交。首次部署前應確認建置的 publish-inputs.json 與程式無私密資料。

## 存檔與更新

- 進度存在裝置的 localStorage。沒有玩家雲端帳號或自動跨裝置同步。
- 設定 → 完整存檔備份／恢復，匯出 `three-kingdoms-full-save` v1 JSON。包含已儲存的主進度、劇情、背包、隊伍、戰鬥、教學、回顧等；不含GM沙盒與開發用人物編輯草稿。
- checksum 用來發現不完整檔案，不是防作弊簽章。
- 匯入先檢查格式與摘要，再確認覆蓋；保存覆蓋前副本，匯入失敗回復原存檔。其他頁會阻止繼續寫入舊狀態。
- 使用相同 HTTPS 網域保存進度。從 file 網址、不同網域或其他瀏覽器搬家時，先在原環境匯出，再匯入。
- 遊戲更新不清除存檔；新格式須新增版本遷移與測試，不得無聲重置。
- 更新先下載整套核心檔案，全部遊戲視窗回主城閒置才切換。基本程式與第一章自動下載，其他章節在進入時或設定中的章節下載頁選擇後完整下載，未變檔案沿用；失敗或斷線保留已完成檔案，下次補齊。頁首與設定顯示進度，出現「已下載章節已備妥」才代表這些章節可離線遊玩。保留候選圖不自動下載。
- 未來 App 必須支援相同備份格式；不宣稱可直接讀取瀏覽器儲存區。

目前已實作的本機玩法可在離線資料備妥後使用。瀏覽器可能回收快取，連網後會補齊；玩家存檔仍應另外匯出。雲端同步、線上對戰與 App 包裝不是此版本功能。



章節歸屬由 `離線章節設定.json` 管理；新增場景必須設定 sceneRules，未歸類圖片會讓建置失敗。章節下載偏好保存在獨立快取，與玩家存檔分離，已選章節更新後繼續維護。新裝置需重新下載素材。

下載完整性：每次啟動、恢復連線、返回遊戲及定期檢查都重新核對實際位元組長度與 SHA-256，不信任舊完成標記；寫入後再次讀回驗證，缺檔或損壞只重抓該檔。未驗證完整不標成已備妥；讀取時也拒絕使用已損壞快取。
